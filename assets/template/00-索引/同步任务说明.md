# 同步任务说明

本文件是每日整理和每周复盘的唯一规则。不管由哪个 AI 工具执行，都读这一份；各工具的定时任务只写一句“按本文件执行”，不在各自的配置里另写一套。

记忆库位置：`~/ai-memory`（不一样的话，全文替换成你的路径）。时间按系统时钟计算，时区按你所在地区。

## 数据来源

先确认你用的工具会把对话保存在哪里，填进下表。只读这些来源，不修改、不移动、不上传。

| 来源 | 本机位置 | 状态 |
|---|---|---|
| 收件箱 | `00-索引/收件箱.md` | 已接入 |
| Codex | `~/.codex/sessions/年/月/日/` 下的 `.jsonl` 文件 | 用的话改成“已接入” |
| Claude Code | `~/.claude/projects/` 下各项目的 `.jsonl` 文件，按修改时间筛选当天 | 用的话改成“已接入” |
| WorkBuddy | 对话存在应用自己的数据库里，暂不直接读取 | 靠收件箱 |
| 【其他工具】 | 【先确认位置再填】 | 待接入 |
| 网页版聊天（无本地记录） | 无 | 只能靠收件箱 |

读不到的会话标记“部分完成”，并写明原因。不要凭标题、预览或文件时间补写内容。

## 多个工具共用时

任何装了 ai-memory-kit 的工具都可以执行整理，但同一时间只能有一个在做，否则会重复处理收件箱。

- 开始前看 `00-索引/.整理中`：文件存在，且里面的时间在两小时以内，说明别的工具正在整理，直接结束并告诉用户。
- 否则创建这个文件，写入当前时间和自己的工具名；整理结束（包括失败）时删除它。
- 定时整理只在一个工具里设置。在 `00-索引/同步状态.md` 开头写明由哪个工具负责，其他工具只做手动整理和实时记录。

## 每日整理

1. 读 `00-索引/读取协议.md` 和 `00-索引/同步状态.md`。
2. 按上表收集当天的对话。每个对话记录：使用的工具、做了什么、用户明确要求了什么、定了什么、产出了哪些文件、还有什么没做完。
3. **提取习惯与画像信号**，这是重点。只记用户本人的话和行为，不记 AI 的建议：
   - 明确声明：用户说“以后、记住、默认、每次、别再、我喜欢、我不要”等。
   - 纠正：用户否定了 AI 的做法，并给出替代做法。
   - 重复选择：用户在相同的决策点多次做出同样的选择。
   - 撤销：用户推翻了自己以前的要求。
   每条记录：日期、工具、项目、类型、用户原话摘录（四十字以内）、适用范围。
4. 写 `03-每日记录/YYYY-MM-DD.md`，模板见 `03-每日记录/_每日记录模板.md`。文件已存在就补充，不覆盖。
5. 把当天的信号并入 `01-用户记忆/待确认偏好.md`：同一条偏好合并计数，列出每次出现的日期和来源。
6. 按下面的提升规则，把达标的条目写进 `01-用户记忆/` 的对应笔记。
7. 收件箱里已处理的条目移到当天的每日记录，收件箱只留说明。
8. 更新相关的项目页、`00-索引/项目索引.md` 和 `00-索引/同步状态.md`。

## 提升规则

| 情况 | 处理 |
|---|---|
| 用户明确说“以后都这样、记住、默认” | 当天直接写进长期记忆，置信度高 |
| 同一偏好在两个以上不同任务里出现三次以上 | 写进长期记忆，置信度中；再出现时改为高 |
| 只出现过一次，或只适用于某个项目 | 留在待确认，或只写进该项目页 |
| 新要求和旧记忆冲突 | 以用户最新的明确要求为准；旧条目标记“已作废”，写明日期和原因，不删除 |
| AI 自己的推断 | 只能留在待确认 |

写进长期记忆的每一条都要注明：内容、来源（日期、工具、项目）、置信度、最后确认日期。

## 每周复盘（每周日，在每日整理之后做）

1. 读取上一次复盘之后的全部每日记录。如果超过一周没复盘，就把漏掉的时间合并成一份，写明覆盖范围。
2. 写 `04-每周复盘/YYYY-Www.md`，模板见 `04-每周复盘/_每周复盘模板.md`：合并重复、提升稳定习惯、降级或作废过时内容、更新各项目的当前进度。
3. 重写 `00-索引/AI启动卡.md`，控制在八十行以内。保留用户亲手写的内容；新增或修改的地方，在复盘里列出来给用户确认。

## 边界

- 只修改记忆库文件夹里的文件，不碰其他项目的文件，不删除任何文件。
- 不写入密码、API Key、Cookie、Token、设备标识和无关的个人敏感信息。
- 最后回复当天每日记录的路径，加一句结论；在 `00-索引/同步状态.md` 末尾追加本次运行记录。
