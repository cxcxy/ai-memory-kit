# ai-memory-kit

**知识库以资料为中心，记忆库以你为中心。**

把背景、习惯、项目决定和实践经验留下来，让多个 Agent 用同一份记忆。普通文档保存在你自己的电脑，可以查看、纠正、备份和迁移。

## 怎么开始

把这个仓库地址发给能读取本地文件、执行 Python 的 Agent，说：

> 请读取这个仓库的 SKILL.md，帮我安装并搭一个自己的记忆库。让我选择读已有 Agent 记忆，或直接发介绍；你来整理和接入，我集中核对一次。

已有 Skill 安装方式的工具也可以先安装，再说“帮我搭一个自己的记忆库”。如果你习惯手动安装，例如 Codex：

~~~bash
git clone https://github.com/cxcxy/ai-memory-kit.git ~/.codex/skills/ai-memory-kit
~~~

已有同名目录不要覆盖，交给 Agent 检查。首次接入会预览需要增补的入口，备份识别为本 Skill 的初始安装，再接到共同的记忆正本。你不用自己搬目录或改配置。

需要 Python 3.8+，脚本只用标准库。当前重点验证 macOS 文件流程；工具版本、文件访问权限和真实新会话效果要在各自环境验证。

## 只选一种来源

**1. 读取已有记忆。** Agent 列出本机找到的记忆文件，你选哪些，它只读哪些，再提炼一页启动卡。

**2. 自己发介绍。** 像聊天一样发一段就好，身份、常用工作、偏好和最近项目写多少都可以。未提供的内容不会替你补齐。

两条路都先给你一份简短草稿。你可以一次回复“基本对，第二条改成……”，同时确认建库位置与要接入的工具。默认位置为 ~/ai-memory。

当前工具要求登录时，在原工具界面登录；已落盘的本地记忆通常不需要额外登录。本版不自动登录抓取其他平台的云端记忆，找不到本地来源就走第二条路。

## 多个 Agent 怎么共用

说“把这份记忆库也接到另一个 Agent 上”。两个工具能访问同一份文件并接好入口后，新对话会按规则读取。

新决定先保存并确认。Skill 会把项目页、偏好和启动卡一起更新；另一个 Agent 再重新读取。不是所有聊天窗口实时互传消息。

配置完成后，新开对话问：

> 我现在这个项目有哪些已经确认的要求？请指出依据文件。

再让它做一个小任务，核对是否实际遵守。

## 怎样积累自己的经验

你可以直接说：

- “把这次决定和原因记下来，只用于这个项目。”
- “这个方法实际有效，把结果和适用条件留在项目里。”
- “周报以后用自然段，把原来用表格的要求撤销。”
- “帮我整理最近的记忆，看看哪些值得留下、哪些已经过时。”

Skill 保存决定、原因、结果、范围、日期和来源。用户明确确认后才进入正式记忆；推断和矛盾留待确认。你只核对结果，不需要亲自填参数。

定时整理和 Git 备份可等用顺后再设置；只指定一个整理负责人。对已有库，不会整体覆盖你的手写规则。

## 文件和权限

记忆正文主要是 Markdown，少量 JSON 保存待处理记录及确认索引。Skill 正本位于记忆库 .kit/ai-memory-kit，各工具链接到这一份；不能用软链接时会用受管理副本，重跑接入可备份更新。

入口文件修改前预览并备份，陌生同名目录与破损标记会停下。增补用户级入口会影响该工具的其他项目。断开只处理自己的区块和安装，保留用户记忆与其他规则。

不记录密码、API Key、Cookie 或 Token。脚本不主动上传数据；云端 Agent 读到的内容可能进入模型上下文，只提供你愿意让所用工具处理的内容。
